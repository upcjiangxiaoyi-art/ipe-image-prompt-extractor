# 🐚 小海螺 · IPE（Info & Prompt Extractor）

SillyTavern 双管线辅助插件：**生图提取** + **挂账账本**。

## 2.27.5 · 改楼不重挂

- 2.17.0 起，改了现任账本那一楼的正文，那楼的账会作废，自动挂账开着就马上按改后的正文重挂一遍。改个错别字、调个格式也多花一次挂账的钱，打开编辑框原样保存也会重挂。
- 现在改楼一律不自动重挂：账本先不动，状态行提醒「账本还是按改前的正文记的，改的是剧情就点「重新挂账」」。打开编辑框原样保存（正文其实没变）不提醒。
- 挂账途中改了那楼：那份账照常落下，状态行同样提醒。手动预览、被拦下等「强制采用」的那份也一样，照常能采用，状态行说明是按改前记的。换了一条 swipe、删了楼照旧作废。
- 点「重新挂账」重挂同一楼（自动挂账已经落了这一楼）：底稿退回这楼之前那一版，不拿已经记过这楼的那份当底稿，伤势轮数这类计数不会重复加。喂给副 AI 的跟当初挂这一楼时一样，只差正文，前缀缓存照样吃得上。
- 改更早的楼：那楼的事已经写进后面每一版账里了，状态行提醒得在账本里手动改掉对应那条。
- 验证：`npm test`【40】按新规矩重写，【50】【52】跟着改（共 540 项），新规矩在 2.27.4 上有 10 项不过；其余六套照常通过。

## 2.27.4 · 每楼只挂一次

- 2.27.1 起挂账落账前要对一眼那楼「改没改过」，当时是逐字比正文。可开着自动生图注入时，副 AI 还在挂账，生图那边就把 `<draw>` 段贴到了楼尾：贴的时候会顺手去掉正文末尾的空行，画风模板不是标签包着的还剥不干净。逐字一比就当成改过，账作废再挂一遍，每楼挂两次（第二次跟第一次几乎一样，所以缓存命中九成九）。
- 现在「改过」只认酒馆的改楼事件（在酒馆里编辑改楼时会发），加上换了 swipe、删了楼这两种；插件自己贴生图段、换画风重注入都不算改楼。
- 同一楼的重复「收到新楼」通知也认得出来：正文多了生图段，还是算同一楼，不再挂。
- 真在酒馆里改了楼，照旧作废，按改后的正文重挂。
- 验证：`npm test` 新增【52】（共 538 项），其中 3 项在 2.27.3 上不过；【50】里强制采用那项改成照真实情况发改楼事件；其余六套照常通过。

## 2.27.3 · 想和写分开报

- 挂账中的状态行分两段报：副 AI 还在思考时报「正在思考，已想 N 字」，思考收尾、开始写正文才换成「正在写账本，已收 N 字」，字数只算正文。
- 思考放在 reasoning 字段里的照旧认；有的中转把思考用 `<think>…</think>` 包着、混在正文开头发来，以前这段被当成「正在写账本」在数，现在也算思考。
- 收完以后开头那段 `<think>` 剥掉再取账本：副 AI 没写包裹时，整段思考不会被当成账本落下；只想没写的按「回了个空」报失败，带上思考字数，账本不动。
- 中转压根不把思考发过来的（GPT 官方接口默认不给思考原文），思考阶段只能显示「等副 AI 开口」和秒数，数不出字。
- 验证：`npm test` 新增【51】（共 534 项），在 2.27.2 上有 5 项不过；其余六套照常通过。

## 2.27.2 · 钉子记在聊天里

- 2.27.0 账本历史「攒两楼再换」的钉子，以前只记在页面内存里。手机上切出去看一眼别的 App 或标签页，Safari 常常在后台把酒馆页面重新载入，钉子一丢，每楼都从最近几版重新钉：缓存永远停在旧账开头，中转后台每楼命中的数一模一样。
- 现在钉子记在这个聊天自己的数据里，页面重新载入、换台设备打开同一个聊天都接得上。钉子挪了才写，隔一楼写一次。
- 挂账成功的状态行后面多一句：「旧账接着上一发」= 这一发从开头到旧账末尾都跟上一发一字不差，中转那边应该命中一大截；「旧账重新起头」= 这一发只能命中到规则、本卡要点、User 指令那一段。攒满以后两种隔一楼轮着来。
- 对照中转后台的数：状态行说「接着上一发」、后台命中的还是固定那一点，就是中转那头只缓存了前面一段，不是插件的事。
- 验证：`npm test`【48】加了页面重新载入和状态行两项（共 528 项），这两项在 2.27.1 上不过；其余六套照常通过。

## 2.27.1 · 不留幽灵账

- 删楼、重 roll、改楼本来就会撕掉那楼的账；重 roll 生成新回复时，账在主 AI 拼 prompt 之前就撕了，贴耳换回上一楼的。这些照旧。
- 补上的是「挂账请求还在路上」那几十秒的空子：这时候删了那楼又马上发新消息、左右滑回已有的那条回复、或者改了那楼，晚回来的那份账以前照样落账，当场贴进主 AI 的耳朵，下一楼还拿它当底稿往下记——记的是已经不存在的剧情。
- 现在落账前先对一眼那楼：楼还在、显示的还是那条、正文没改（生图后来追加的 `<draw>` 段不算改），才落账；对不上就作废，状态行写明。换了 swipe 或改过的，自动挂账开着就按现在这条重挂；发送前等挂账的会接着等，这一发读到的是新账。
- 滑回已有的那条回复（没重新生成）：以前只撕掉刚才那条的账，这条的账一直缺着；现在自动挂账开着就给这条补挂。右滑重新生成、新回复还在出字时不抢，收到新楼照常挂。
- 手动预览、被保护闸拦下的「强制采用」：结果出来以后那楼删了、roll 了或改了，就不让采用，提示按现在的正文重挂。压缩结果出来以后账本变了（又挂了一楼、被撕回去、手改过），压缩结果作废，不再把旧账盖回来。
- 挂账失败、等重试的几秒里那楼删了，就不重试（以前会掉头给更早的一楼再记一遍）。
- 场景标记跟楼走：被 roll 掉那条写着 nsfw、新的一条没写标记时，不再沿用被 roll 掉那条的标记，退回还活着的楼里最后一个标记。
- 验证：`npm test` 新增【50】（共 526 项），同一套测试在 2.27.0 上有 12 项不过；其余六套照常通过。

## 2.27.0 · 旧账攒着换

- 挂账请求里的「账本历史」不再每楼往前挪一格。以前每来一楼就挤掉最老的一版、接上最新的一版，开头一变，副 AI 那头的前缀缓存就从这里断，后面几整份账本加正文全部重新计费。
- 现在把上一发喂的最老那版钉住，新落的一版只往后接；接到比旋钮多一版，下一发再跳回最近几版重新钉。旋钮 3 版：旧账 2 版、3 版轮着来，再加现任。没跳的那一发，账本历史整段跟上一发一字不差，吃得上缓存；跳的那一发断一次。
- 代价是隔一楼副 AI 多看一版旧账，平均每发多 5% 左右的字；该看的旧账一版不少。旋钮 1 版（只带现任）的没得攒，照旧。
- 账本历史挪到剧情摘要前面：两块每楼都往后接新东西，排在前面那块一接新的，后面那块就跟着断，只有排前面的吃得到缓存。账本历史是几整份账本，比四五条摘要大得多。
- 每版账本统一标「第 N 楼时版本」，段头写明「最后一份是当前版本」。现任那份下一楼变成旧版时标题一字不变，这一整份也吃得上缓存。
- 钉在哪只记在内存里、按聊天认：刷新页面就从最近几版重新钉，顶多断一次。面板估字数是干跑、不挪钉子，重 roll 本楼时请求跟上一发一字不差。
- 模拟（默认挂账规则、账本历史 3 版，连挂 30 楼）：剧情摘要近 10 楼的命中 45% → 59%，没写摘要的 48% → 62%，摘要开到近 40 楼的 38% → 51%。
- 现在的顺序：挂账规则（system）→ 本卡要点 → User 指令 → 账本历史 → 剧情摘要 → 这次额外要求 → 当前楼层 → 本轮正文。
- 修：压缩账本时「额外说一句」写了不生效。压不下去时提示叫人在这里点名哪段该合并再重 roll，压缩请求里却没带这一句。现在带上，排在压缩指令后面、包裹要求前面；没写的跟以前一字不差。
- 验证：`npm test` 新增【48】【49】，【47】改成新顺序（共 505 项）；其余六套照常通过。

## 2.26.4 · 补充垫底

- 挂账投喂的段落按「多久变一次」排，越稳越靠前：副 AI 那头的前缀缓存只认从头起一字不差的那一段，中间哪段变了，它后面全部重新计费。
- 「这次额外说一句」以前排在 User 指令后面：手动挂账改一句补充再重摇，剧情摘要、账本历史整段都得重新算。现在挪到账本历史后面、当前楼层前面，前面整段都能吃上一发的缓存。
- 这一版的顺序：挂账规则（system）→ 本卡要点 → User 指令 → 剧情摘要 → 账本历史 → 这次额外要求 → 当前楼层 → 本轮正文（2.27.0 起账本历史挪到剧情摘要前面）。
- 自动挂账不带额外要求，发出去的内容一个字没变。它吃不满缓存的原因不在顺序：剧情摘要和账本历史每楼都往前滑一格（最老的一条摘要、最老的一版账挤出去），请求从剧情摘要第一行起就和上一楼对不上，后面的账本和正文只能重新算。
- 验证：`npm test` 新增【47】（共 492 项），其余各套照常通过。

## 2.26.3 · 潮汐回响回到楼尾

- 有的美化会把楼里的几块重新排座：把 `.mes_block` 设成 flex 再给正文 `.mes_text` 一个 `order`，或者用 grid 按格子摆。2.25.0 起 🐚 潮汐回响挂在正文后面（正文外），在这类美化下就被排到了名字底下、正文上面。
- 现在放 🐚 时先把正文的 `order` 抄给它：flex 里 order 相同的按先后排，🐚 就紧跟在正文底下。2.25.0 的好处都留着，正文被整块重写时碰不到它，楼尾不会一缩一伸。
- 放好以后量一眼：🐚 还在正文上面（grid 格子、定位这类，抄 order 也没用）就退回 2.25.0 以前的老办法，放进正文末尾，这个聊天里以后都这么放；换聊天重新量（不少卡自带美化样式）。这类美化下正文整块重写时它会被抹一下，观察器当场补回。楼尾生图段照样贴在 🐚 前面，顺序还是 正文 → 生图段 → 🐚。
- 没重排楼内块的美化什么都不变。只在放块、挪块、这一楼还没量过的时候量一次，量过的楼只换字不碰排版。
- 验证：`npm run test:smooth` 加了 flex + order、grid 格子两种美化的场景（共 60 项），其余六套照常通过。

## 2.26.2 · 画风模板

- 「基础模板」改叫 **「画风模板」**：大家说「基础模板」不好理解、有时候找不到。面板区块、酒馆抽屉里的卡片、⤢ 放大编辑框标题、「公共块」和「换画风重注入」旁的说明、删到只剩一个时的提示，都统一成新名字。
- 只改叫法：已存的模板、选中的那套、公共块挂接、画风包导入导出一个都不动（存储键和控件 id 没变）。

## 2.26.1 · 开口时限

- 生图提取正常几十秒就完。现在发出去 **120 秒还没写出正文第一个字** 就掐断、自动重来一次（重来成功照常自动注入）；**重来还不开口**，弹一张要手点「知道了」的常驻卡，点名这个模型，劝换 API 预设或模型。
- 光在思考、中转一直发心跳包都 **不算开口**。2.26.0 的看门狗只看有没有字节，这种「连接活着、就是不出字」的永远判不死。
- **开口之后不卡时限**，写得慢也不掐，只防中途断流：连续 240 秒一个字节都没有才断，按普通失败走（弹卡、重试一次）。
- 第一次没开口不弹窗，只在状态行说明卡在哪（连响应都没等到 / 一直在想 / 连上了但一个字没写）和「10 秒后自动重来一次」。
- 没开口时状态行和实况框的秒数带上时限，如「35 / 120 秒」，看得出还剩多久。
- API 配置区的「空闲超时」改名「开口时限」（秒，0 = 不限）；2.26.0 里自己改过的数（含 0）升级后自动带过来。
- 「🔍 自动提取人物外貌」资料多、要想得久，也没有自动重试，不卡开口时限，照旧只防断流。
- 验证：`npm run test:stream`（53 项）。

## 2.26.0 · 生图流式

- 生图提取（手动提取、自动提取、重新生成、单层重摇）和「🔍 自动提取人物外貌」改走流式（`stream:true`），跟挂账是同一套读流和看门狗。以前是整包干等：思考模型、慢中转半天没动静，看不出连没连上，有的中转见连接闲着还会半路掐断。
- **状态行按阶段走字、秒数每秒跳**：连接中 → 已连上，等模型开口 → 模型思考中，已想 N 字 → 模型输出中，已写 N 字。卡在哪一步一眼就知道。
- **预览区新增「实况」框**：思考（`reasoning_content` / `reasoning` / `reasoning_details`，或正文开头的 `<think>…</think>`）和输出原文边收边显示。跑完也留着，标题写「✓ 完成 · 思考 N 字 · 输出 N 字 · N 秒」，失败 / 手动中止也标出来。能折起来，记住开合。
- 正文开头的 `<think>…</think>` 算思考，不再混进生图描述。
- API 配置区新增 **「流式接收」**（默认开；关了就是老的整包干等，秒数照跳）和 **「空闲超时」**（默认 120 秒，0 = 永不）：不是总时长，是连续这么久一个字节都没收到才判死，首字到了放宽一倍；判死算一次失败，照常自动重试一次。以前生图请求没有任何超时，中转卡死就一直停在「正在提取…」。
- 中转不认流式、整包 JSON 回来的，照整包解析；HTTP 报错文案、自动重试、「打断请求」都照旧。
- 顺手修：酒馆抽屉的生图页，2.23.0 加「公共块」之后卡片名字错了一格——置顶展开的其实是「提取规则」，真正的预览（状态行、提取 / 打断按钮）压在最底下还折着。现在预览置顶展开，七张卡名字对上（记住的开合状态会按新名字重来一次）。
- 验证：`npm run test:stream`（假中转按时序吐 SSE：边收边看、think 拆分、整包兜底、开关、看门狗、打断、截断报因、分层标签跨块）；另用 Chromium 按手机宽度实跑过一遍流式读取。

## 2.25.0 · 楼内不跳

注入的内容、时机、自动注入 / 自动挂账的流程和贴耳一概没动，只改小海螺往聊天区里放东西的方式。

- **🐚 潮汐回响挂到正文后面**（`.mes_text` 的下一个兄弟），不再塞在正文里。酒馆流式、滑动、改楼、`updateMessageBlock`，前端卡 / 变量框架重写正文，都是把正文整块换掉；以前块跟着被抹、隔 250ms 才补回来，楼尾一缩一伸，补的时候又动了正文，盯着正文的美化还会再重画一次。现在重写正文碰不到它，重 roll 时它一直在楼尾当页脚，字在按下重 roll 那一刻就换成对账后的那份。样式照正文抄了字重、行高和右侧留白，看上去和以前一样。
- **新楼到了同一帧挪过去**：和酒馆画完最后一帧同一轮（以前晚 500ms），酒馆紧跟着的「滚到底」会把它一起带进视口；整楼被换掉、整段聊天重画时，在浏览器画下一帧之前就补好，看不到「没了又冒出来」。
- **视线不跳**：小海螺在聊天区加 / 摘 / 改自己的东西（🐚 块、楼尾生图段、🎨 按钮）前后，按「视口里第一条在视口内开头的楼」钉住位置，改动发生在它上面就把 scrollTop 补回去。上一楼摘掉 🐚、往视口上面的楼注入、换聊天时给一串旧楼挂 🎨（窄屏可能把楼头挤成两行），眼前的字都不再被顶一下。Chrome / Firefox 自带滚动锚定时量出来差 0，不会补两遍；iOS Safari 没有滚动锚定，靠这个。
- **绘画注入**：贴进楼里的还是那串原文，一字不改；多了个类名，让换行照原样分行（酒馆重画后换行也是一行一行的），重画前后高度差不多。顺序固定为 正文 → 生图段 → 🐚，不会重画一次换一次位置。
- **换画风原地换**（面板按钮 / 楼层 🎨）：新段放在旧段原来的位置。那楼被酒馆重画过（刷新后翻回去点 🎨 最常见），也按字认出旧段一起换掉，不再旧的留着、新的叠一段、楼一下子长一截；认不准（楼尾是前端卡 / 图、字对不上）就一个都不摘，照老样子追加。

## 2.23.0 · 画风模板公共块

- 画风模板里各自内嵌的通用规则（人物族裔 / 年龄 / 性别、人物区分、解剖与手、视线不看观众、无文字水印）抽成**公共块**，画风正文只写画风本身。「公共块」区可以建多份（例如「通用」「古风」），收尾句放在公共块末尾。
- 每个模板在「基础模板」区的「挂公共块」里选挂哪一份，或不挂。拼接顺序：场景五段（Camera / Env / Mood / Chars / Pose）→ 画风正文 → 公共块。
- 模板里写了 `{Common}` 就放在那个位置；没写就自动插到 `</draw>` 前一行（不是 `<xxx>…</xxx>` 包裹型的模板追加在末尾）。不挂时 `{Common}` 独占的那一行整行去掉。
- 防重复：模板正文里已经原样带着这段公共文本（空白不同也算）时，不再叠一份。
- 批量挂接：名字含某关键词的模板（留空 = 全部）一次挂到指定公共块，或批量改为不挂；执行前列出将被修改的模板名单确认。
- 删除公共块时，挂着它的模板回落为不挂，并列出受影响的模板。
- 画风包格式升到 `_v: 2`：带 `commons`，模板带 `common` / `commonName`，导入按名字合并公共块再对上模板；「只导出当前这套」只带当前模板挂的那一份。旧版包（没有公共块）照常导入，导进来的模板默认不挂；本地有公共块时会问一句要不要挂，默认不挂。
- 挂账剥楼尾生图块：非包裹型模板后半段或公共块改过后，老楼的后缀对不上时退回按前缀剥到楼尾（注入永远在楼尾），不再整块漏进挂账正文。

## 2.22.4 · 入镜判断更稳

- 以前只认副 AI 的 `<cast>`：它写 NONE、写拼音或漏人时一个外貌都不贴，可规则又叫它别写外貌，结果描述里只剩「陆籍北 stands…」没有长相。现在 `<cast>` 点到的，加上描述里写到名字 / 别名的，都算入镜、照贴外貌。
- `<cast>` 对不上号时，状态行会写出副 AI 写了什么；浏览器控制台有 `[IPE] 🧷 人物锁` 明细。

## 2.22.3 · user 叫「你」也锁得上

- 正文大多用第二人称「你」称呼 user，副 AI 不知道「你」是谁，`<cast>` 就漏报，user 的长相贴不上。现在人物锁约定里会点明「你」就是 user（按酒馆里的 user 名认出对应的人物段），要求 `<cast>` 和描述里都写 user 的名字；副 AI 在 `<cast>` 里写「你 / you / user」也照样认成 user。
- 约定里原本用「你」称呼副 AI，容易和 user 混，改掉了。

## 2.22.2 · 默认男帅女美、大眼有神

「🔍 自动提取人物外貌」的内置提示再加三条：
- 主角、user 和重要人物默认男帅女美，五官往好看里写具体；只有资料明确写了丑、相貌平平或毁容才照写。
- 资料没写特别眼型（单眼皮、狐狸眼、丹凤眼等）时，一律写 large, bright, expressive eyes with double eyelids，防止生图把东亚人画成单眼皮小眼睛；资料写了特定眼型就照资料。
- 只写稳定长相，不写也不放大肮脏、邋遢、贫穷、落魄、疲惫、憔悴、狼狈这类状态。

## 2.22.1 · 外貌不写 skin

- 敏感提取规则禁止输出 skin 等词，但人物锁贴进提示词的外貌行不经过规则。现在自动提取时要求肤色用 complexion 写，整理结果里残留的 skin / skin tone 也自动换成 complexion。已经提取过的锚点，再点一次「🔍 自动提取人物外貌」就会更新。

## 2.22.0 · 人物锁只锁长相

- 「🔍 自动提取人物外貌」只整理**性别、年龄、长相**这一行（25～50 词）。特别交代副 AI 把发色写准：具体颜色，带上深浅、挑染、渐变，再写发型长度；有辨识度的特征（痣、疤、纹身、眼镜、耳钉、异色瞳、雀斑等）一定写进去，放在靠前的位置。
- 不再提取服装和别名。服装回到每楼由副 AI 按剧情照常写；「本聊天服装」记录、服装框和换装标签都去掉了，「更多」里只剩提取温度。
- 每楼发给副 AI 的锚点，锁定人物只省掉外貌那一行，标题和人物段里的其他行（比如手写的备注）照发。
- 2.21 提取出来的预设照样能用，里面的服装、别名行不碍事；想换成新格式，再点一次「🔍 自动提取人物外貌」就会覆盖同一套。

## 2.21.0 · 自动提取人物外貌 🔍 + 人物锁 🧷

目标是人物每楼长得一样，而且用户什么格式都不用学。

## 双管线

**生图管线**：从 RP 正文提取场景描述，调用独立 API 生成英文生图提示词，可注入回正文（默认包成 `<draw>…</draw>` 追加在楼尾，模板可自定义）。支持多 API 预设一键切换、基础模板 / 角色锚点 / 提取规则 / 双 System Prompt 预设、失败弹窗与一次性自动重试、请求打断。**换画风重注入**：提取结果不动，换个画风模板一键把楼尾那块 `<draw>` 重拼替换，不再调副 AI。注入时把描述和五层记进那楼，每条记过的 AI 楼操作栏里有 🎨，翻到哪楼点哪楼。补充指令可存常用短语，点一下填进去。可选**分层提取**：一次请求拆成镜头 / 环境 / 氛围 / 人物 / 动作五层，每层可锁、可单独重摇，环境层与氛围层在不变时自动沿用上一楼。模板里可以同时写五个层占位符和 `{Description}`：哪一行的占位符全空，那一行整行不输出，分层开关开不开都是同一张模板。

**挂账管线**：由副 AI 维护的不透明账本，仅凭定界符对与 NO_CHANGE 哨兵识别，逐聊隔离，带版本历史回滚（最近 6 版 + 每 10 楼一个里程碑 + 每 100 楼一个里程碑）与缩水保护；删楼、重 roll、改楼都会把已不成立的账撕掉；手动模式走"预览 → 采用 / 重摇"流程。请求走流式接收（思考模型可用），空闲看门狗兜底，不会挂死。副 AI 还在挂账时发下一条，酒馆会先等账落下再送（generate_interceptor）；网络错自动重试一次；同一张卡开新聊天可一键继承上个聊天的账本。账本写长了可以「压缩一版」，副 AI 合并已了结的支线、精简语言，先预览再采用。

## 浮标与状态指示

聊天区快捷入口为「月灰入米霜」SVG 胶囊（涟漪呼吸动效），自由拖动，点击开小面板；亦可由避风塘 Harbor Bar 收编进顶栏泊位，两种形态同一套皮肤。

胶囊自带三种状态指示：

- **雾霾蓝脉冲 + 左侧蓝灯**：挂账进行中——此刻贴耳仍是上一份账本，先别发下一条
- **月灰脉冲**：生图提取进行中
- **右侧绿点**：提取完成、待注入
